Firmware · STM32WBA55CGU6 · FreeRTOS + Zigbee

Frostkern FreeRTOS runtime design

How the motor-cooling firmware is split into FreeRTOS tasks on one master and two slave boards, how those tasks share data, and how the slaves sleep on battery without losing control of the fan.

Status agreed, v1 Date 2026-11-10 Source firmware/docs/freertos-plan.md

01System overview

All three boards use the same PCB (wba55_v1). One codebase builds two configurations, ROLE_MASTER and ROLE_SLAVE. The role decides which application tasks start and which Zigbee library gets linked (FFD for the master, RFD for the slaves).

Master ×1

Zigbee coordinator · never sleeps

  • Powered from the car's 12 V battery through a step-down module
  • XIAO ESP32 is a Wi-Fi bridge to the app over UART
  • ESP32 power switched by ESP32_EN to limit drain on the car battery
  • No sensors, fan or pump

Slave ×2

Zigbee sleepy end device · 4×AA

  • 1 NTC thermistor, 1 YF-B7 flow sensor
  • PC fan and pump on an external supply, switched by MOSFETs
  • Runs its own PID loop; the master only sends the setpoint
  • Pump is plain on/off

06Zigbee stack rules

  • Stack: Exegin Zigbee R23, shipped as precompiled libraries: ZigBeeProR23_FFD.a (master), ZigBeeProR23_RFD.a (slaves), ZigBeeClusters.a.
  • Starting points: Zigbee_OnOff_Server_Coord_FreeRtos for the master. There is no FreeRTOS sleepy-end-device example, so the slave combines the FreeRTOS structure of Zigbee_OnOff_Client_Router_FreeRtos with the sleep settings of Zigbee_TempMeas_Server_SED.
  • Radio interrupt priorities from ST's app_conf.h: high 5, low 7, software-low 14, RCC 1. Our own interrupts that call FreeRTOS go in 6–13.
  • Only ZbAppTask calls Zigbee APIs. Never call them from an interrupt.

07Low-power modes (slaves)

A slave spends most of its life in idle mode, which is where the battery savings come from. It switches to active mode as the motor warms up, with hysteresis so it doesn't flip back and forth. Every number is a #define in one config header.

Active modeIdle mode
Enter whentemp ≥ setpoint − MARGIN (e.g. 5 °C)temp < setpoint − MARGIN − HYST
Sampling2 s, PID runs30 s, fan off, no PID
Report to masterevery 60 s, or temp moves > 0.5 °C, or faultevery 5 min, or change, or fault
Parent pollevery 10 severy 60 s
Sleep depthStop 1 if LPTIM2 PWM survives it, otherwise Sleep while the fan runsStop 1

Hardware facts behind this

  • The WBA55 has Stop 0, Stop 1 and Standby. It has no Stop 2.
  • LPTIM1 counts pulses on PA0 in Stop 1. ST ships this exact example (LPTIM_PulseCounter, NUCLEO-WBA55CG).
  • Regular timers (TIM1/2/3/16/17) stop in Stop mode, so the fan PWM must come from LPTIM2 on PA1.
  • ADC4 can convert by itself in Stop 1. DMA only runs in Stop 0.
  • The independent watchdog keeps counting in Stop, so the supervisor must wake up before it expires.

Check on hardware first: does LPTIM2's PWM output keep toggling in Stop 1? That decides the sleep depth in active mode.

08Zigbee data model

Each slave exposes one endpoint with standard clusters only. There is no manufacturer-specific cluster, and the PID gains are compiled into the firmware.

ClusterIDKey attributesNotes
Temperature Measurement0x0402MeasuredValue (int16, 0.01 °C)Shipped by ST
Flow Measurement0x0404MeasuredValue (uint16, 0.1 m³/h), min, maxPut together by us with ST's generic cluster API
Fan Control0x0202FanMode (off / low / med / high / on / auto)Shipped by ST
Thermostat0x0201OccupiedCoolingSetpoint (int16, 0.01 °C)Master or app writes the setpoint. Confirm ST ships it.
Power Configuration0x0001BatteryVoltage (100 mV), BatteryPercentageRemainingShipped by ST

Pairing

  • The app's Pair button, or the master's physical button, opens joining on the master for 180 s.
  • A slave that isn't on a network searches on its own, waiting longer between tries: 10 s, then 1 min, then every 5 min.
  • Holding a slave's button for 5 s makes it leave the network and reset.
  • Network details are saved in flash, so boards rejoin by themselves after a reset or battery swap.
  • Security: the Zigbee 3.0 default trust-center link key.

10Open questions

  1. Fail-safe policy: sensor fault, lost connection, watchdog behaviour, pump on a flow fault. partner
  2. MQTT or something else between the ESP32 and the app. ESP32
  3. Which PID library to use. research
  4. Does LPTIM2 PWM on PA1 keep running in Stop 1? hardware test
  5. Engine-running detection (12 V level into an ADC) for a later board revision. next board
  6. Install codes instead of the default link key. security
  7. The YF-B7 needs the 5 V boost and its load switch on. Power it all the time, or only in active mode and short windows in idle? power
  8. The standard flow cluster's resolution is 0.1 m³/h (about 1.7 L/min). Is that fine enough? data model
  9. Fan Control has no duty-percent attribute. Is FanMode enough for the app? data model
  10. Not yet checked against the datasheet or reference manual: LPTIM2 in Stop 1, ADC4 autonomy, Standby under FreeRTOS, whether ST ships the Thermostat cluster. verify
