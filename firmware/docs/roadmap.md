# Frostkern firmware — roadmap to the Dec 2 demo

Status: agreed 2026-11-19. Companion to `freertos-plan.md` (runtime design).

## How we work

- You write all the code; Claude guides the next step and reviews.
- CubeMX (GUI) → "CMake" toolchain → VS Code with the STM32Cube extension, STM32CubeCLT toolchain, ST-LINK GDB server. The old system GCC 10.3 and OpenOCD are not used.
- Hardware: the `wba55_v1` PCB from day one, flashed and debugged with the STLINK-V3MINIE. Debug log on USART1 (PB12 TX / PA8 RX) through the probe's VCP. Reset through the ST-LINK (no reset or pair button on the board).
- Tests run on real hardware. Each brick ends with its acceptance check passing on the board, then one commit.
- One branch per codebase: `firmware`, `esp32`, `app`. Merge into `main` only at checkpoints; `main` always holds working code.

## Project layout

```
firmware/
  master/   CubeMX project: Coordinator, FFD. Base: ST Zigbee_OnOff_Server_Coord_FreeRtos
  slave/    CubeMX project: Sleepy End Device, RFD. Base: ST Zigbee_OnOff_Client_Router_FreeRtos,
            switched in CubeMX to END_DEVICE / RFD / sleepy ON
  common/   shared code: config header, IPC types, frame codec, CRC16, NTC math, PID
  docs/
```

- Copy the **whole** example folder, not just the `.ioc`: ST keeps the example's app logic in `USER CODE` blocks (e.g. `STM32_WPAN/App/app_zigbee.c`).
- The Zigbee role lives in the `.ioc` (`ZGB_DEVICE_ROLE`, `ZGB_APPLICATION`, `ZGB_SLEEPY_MODE`, `CFG_LPM_LEVEL`) and drives generated code and linked libs, which is why there are two projects.
- New module files go in `Core/Src` / `Core/Inc`, or `../common`, and are added in the user section of each project's root `CMakeLists.txt`. Only `cmake/stm32cubemx/` is regenerated by CubeMX.
- Our edits to generated files stay inside `USER CODE BEGIN/END` blocks.
- SED reference for join and poll settings: `Zigbee_OnOff_Client_SED`, `Zigbee_PowerConfig_Server_SED` (bare-metal).

Examples live in `~/STM32Cube/Repository/STM32Cube_FW_WBA_V1.10.0/Projects/NUCLEO-WBA55CG/Applications/Zigbee/`.

## Demo scope

**Never cut:**
- Slaves are sleepy end devices with real Stop 1 savings, measured.
- Temperature → PID → fan.
- Telemetry reaches the app.
- Setpoint is set from the app.

**Cut order if behind** (first dropped first):
1. Live current graph (keep multimeter numbers)
2. Fault flags beyond "NTC out of range"
3. Pair button in the app (permit-join at master boot still works)
4. Second slave (demo with one)

## Measuring battery savings

- Now: multimeter in series with the 4×AA pack, µA range, with a bypass jumper across the meter. Boot with the bypass closed (radio start-up peak would brown out through the meter shunt), then open it to read sleep current. Active current on the mA range.
- Firmware logs time spent in each state; average current and days on 4×AA are computed from that.
- Optional: STLINK-V3PWR (ordered from Newark, 4–5 days quoted). STM32CubeMonitor-Power runs on macOS. If it arrives before Nov 28 it gives a live graph and can replace the V3MINIE on the slave.

## Decisions made in this session

| Topic | Decision |
|---|---|
| Toolchain | CubeMX → CMake → VS Code + STM32CubeCLT, not CubeIDE |
| Project base | ST FreeRTOS Zigbee examples, not a blank `.ioc` |
| Roles | Two CubeMX projects + `common/`, not one project with presets |
| Slave Zigbee role | Sleepy End Device (RFD) from the start; MCU low power off during development, spike at B3b, final at B9 |
| Pump | Always on, not controlled by the MCU; PA2 unused (analog) |
| Idle power | Fan off, boost + YF-B7 off except a 2 s flow window every 5 min; NTC every 30 s with pulsed bias |
| Zigbee data model | Standard Temperature, Power Config, Thermostat; one manufacturer cluster `0xFC00` for flow (0.01 L/min), fan duty %, mode, faults. No Flow Measurement or Fan Control cluster |
| Application | Simulated engine coolant loop (gasoline car), bench rig, uncontrollable heater, boards "in the engine bay" |
| Setpoint range | Limits 30–95 °C, demo setpoint 60–70 °C, loop kept ≤ 80 °C (YF-B7 rating) |
| NTC | Believed 50 kΩ / B3950; measure at room temperature before B4. Keep R19 = 22 kΩ if confirmed |
| Zigbee persistence | On for both boards (CubeMX `ZGB_PERSISTENCE`, ST's `*_Persist` examples): master keeps PAN and keys across reboots, slave restores and rejoins without permit-join. Stored in the last 24 KB of flash; chip erase clears it. Decided 2026-11-23 |
| Pairing | No buttons: master permits join 180 s at boot and on `PERMIT_JOIN` from the app; slaves auto-join with backoff; factory reset = chip erase over ST-LINK |
| ESP32 ⇄ app | ESP32 SoftAP + WebSocket, JSON mirroring the UART frame types |
| Fail-safe (minimum) | NTC out of range → fault, fan 100 %, report now. Loop ≥ 80 °C (`FK_OVERTEMP_C`) → `OVERTEMP` fault, fan 100 %, report now, app alarm. Lost parent → keep PID on last setpoint, rejoin with backoff. No flow > 5 s → fault + report. IWDG out of scope |
| PID | Decide at B6; default: own PI in `common/pid.c` |
| UART instances | Debug VCP = USART1 (PB12/PA8); ESP32 link = USART2 (PA12/PA11) |
